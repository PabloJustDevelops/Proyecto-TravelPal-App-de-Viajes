# Estrategia de Branching

## Rama principal
- `main`: estable, desplegable.

## Ramas de trabajo
- `feature/<nombre>` para nuevas funcionalidades.
- `fix/<nombre>` para bugs.
- `chore/<nombre>` para mantenimiento.

## Política de merges
- Usar PRs con review obligatorio.
- Squash & merge recomendado para historial limpio.
